# Independent tracking raw audit contract

Three frozen blocks, three methods, 64 environments, 960 native post frames,
192 case identities and 576 method windows. Comparisons are reference versus
delay reserve (primary), reference versus tight reference, and tight reference
versus delay reserve. Own prior NumPy primitives are reused; parent analysis
functions and parent outcome totals are not inputs.

The single-use supervisor starts one CPU process with at most two condition
threads and one BLAS thread per library. Each thread reads only a terminal
canonical campaign's condition. MemAvailable must be at least 25 GiB before
submission; this is a submission gate, not a hard RSS reservation. No simulation
or GPU work is launched. The supervisor records actual child exit and exits;
there is no automatic retry or orphan polling process after completion.

All three frozen plan hashes, reviewed five policy source hashes, original
source/actor hashes, canonical actual argv, complete child/protocol identities,
new bank assignments, native q0/initial qd/initial target, the 960 executed and
962 stored command frames are bound. Native array dtype/shape/byte fingerprints
govern pairing. Missing or invalid windows/pairs remain unavailable.

Strict is native float32 `<0`; deep is native float32 `<-float32(.005)`.
There is no epsilon. Counts include frame 0 and frame 959, class counts, native
class minima, first steps, window failures and correlated environment-step
durations. No favorable-window summary may suppress an adverse duration result.

All 30 chunks per condition reconstruct four exemption-aware class minima from
9021 full pre-step distance rows and bind 959 preceding post-frame minima. The
last post-frame minima are read from the native cell; no claim is made to a
full final post-row archive. The same target-only admission union is required
in all modes, including baseline preservation, capacity and no dropped rows.
Archived reserve minima/exemptions and chosen gaps are checked. Full J is not
archived each frame, so full frozen-J forecasts cannot be independently
recomputed at every step. Frozen producer finite checks are a separate source
claim, not direct full-J raw evidence.

Adaptive gap arithmetic reproduces the registered PyTorch2.7 CUDA eager scalar
division branch (multiply by an opmath reciprocal), as derived before outcome
reads from its exact installed git commit. This may differ in the last bit from
CPU direct division. See astra_tracking_backend_arithmetic.json and the retained
official source. This is a CPU source-derived check, not a GPU execution result;
native physical scoring thresholds remain unchanged.

All six actual pending slots, delay arrival, controller integration with soft
limits, applied target sequence, effective increment and target debt are bound.
First-six post q/pre qd/post qd/applied-target bit fingerprints are compared
between all registered pairs and differences are reported explicitly. This
does not establish equality of unarchived full rigid state.

First-failure receipt identities are checked for every failed environment.
The first two failing environments by (step,env) per condition receive selected
snapshot/J binding. Actual q motion, actual target integration and applied
target error are distinguished; their signed J diagnostics do not identify a
unique physical cause. No additional LPs or old huge trajectory audits run.

Every consumed raw payload is hashed as read; each condition rechecks its input
hashes and writes a separate persistent checkpoint. The aggregate merges in
registered order and rehashes the whole consumed ledger before final output.
Unselected snapshots and unrelated raw files are outside that hash claim.
Partial checkpoints are evidence, never a completed final score or silent
resume cache. Interruption requires a separately recorded recovery decision.

Camera trajectories, actual pixel inspection, parent LP/report reconciliation
and final scientific review remain separate pending gates. Nominal tracking
reserve and discrete LP samples cannot certify physical safety or continuous
recoverability. No promotion or hardware approval is implied.
