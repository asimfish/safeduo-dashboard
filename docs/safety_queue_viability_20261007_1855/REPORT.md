# 队列、跟踪偏差与可行性开发实验

本轮完成诊断机制与随机线性实验。没有新增机器人控制试验，也未证明物理安全；上一轮零输入候选仍拒绝。

## 新发现

- 211个原始首次失败快照，2,110次选中线性集合分解，再做844次参考边界/authority预算依赖检查。原始严格几何端点仍用native float32 <0m；没有添加评分epsilon或修改豁免。
- 零包含模式7个失败的U集合全部联合不可行，但单行检查均无矛盾；移除alpha行仍全部不可行。因此零增量包含和逐行authority clamp均不保证联合可行。
- 在固定已保存G/h下放宽参考区间至原始速度+软限位可达箱，422个F/U集合均可行；重算authority预算后421/422可行，参考模式1个U集合仍不可行。以上仅数学探针，选择行、输入与alpha仍冻结，不是重算生产策略或执行轨迹。
- 两个新增失败在实际post越界前已有pre-step约束残差报警：seed658533148/env38在t225报警、t620越界（395步）；seed69425290/env38在t165报警、t193越界（28步）。这是残差报警提前量，不是首次联合不可行时间。全帧G未保存，不能确定联合集合最早何时不可行。
- 零包含7个失败全部提前报警，提前28至729步；185个未发生严格越界窗口中162个也报警。未越界报警不是已证明的误报；若把报警直接用作停止条件，将在162个未越界窗口触发停止；对实际活动量和安全的影响尚未通过干预实验测量，不能据此声称安全改进。

## 已完成实验

- 3个新OS随机种子，F14/U12两个维度，4类解析可判定约束，每类每维每种子512，共12,288个新的线性案例。随机非对称命令箱、多关节耦合、实际qd在±5rad/s及六个随机待执行目标。全部匹配预定可行/不可行类别；可行解数值残差小于1e-7；所有未来安全状态保持UNKNOWN。
- 已实现queue_guard.py当前集合检查、联合LP、队列冻结J/CV6风险探针与残差状态。此模块不改命令、不清空队列、不生成恢复动作。当前数值可行不代表未来安全。
- 576个旧机器人方法窗口、552,960个保存帧完成报警时序回读。旧机器人样本仅做开发诊断，未计为新盲验证。
- 10个聚焦机制CPU测试、3个原生快照存储隔离测试实际通过。native_state_capture.py可复制完整getter的q/qd/root/rootvel与控制索引及六个待执行目标；仅CPU桩测试，Isaac集成尚未运行。

## 相机证据边界

旧数值反例仅有受控关节q/qd，缺完整原生关节状态、每臂root transform和root velocity，无法宣称精确原生恢复后渲染。面板复用上一轮封存的47组423张九视角图及原生before/after链接；图像绑定各自相机运行状态，数值轨迹重放已失败。本轮新增相机采集0组。下一轮需在物理步前及render前保存native_state_capture完整字段，再用九视角进行实际绑定验证。
