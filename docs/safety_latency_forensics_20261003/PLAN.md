# 冻结策略后的延迟与回归取证

本轮不新增安全策略候选。沿用未推广的 pending_guard 和固定 a31b actor，对两个既有失效做观察性重播，不增加独立安全窗口数量，也不假定实机支持停机抢占。

1. seed12，32环境，held_random，±0.3rad初态，6步目标FIFO，10秒，保持90步：补齐逐行雅可比、真实求解器cap、历史目标、当前发送目标、全关节/COM速度、球心与豁免轨迹。
2. seed8，32环境，l1_full，原初态、零延迟，5秒：定位此前env9新增桌面违规，使用同样观察器。
3. 与已发布npz逐位核对初态、命令与物理关节轨迹。若观察器改变了轨迹，降级为不同重播，不能把新增证据当作原失败的精确取证。

预先区分以下解释：

- 历史目标虽预测到风险，当前输出没有在真实发送目标处生效：核对FIFO时序与逐行延迟目标闭合量。
- 约束集互相冲突或迭代不足：按真实cap、历史扣减、authority钳制、alpha和目标限位重建半空间，以独立线性规划区分无可行解与求解器残差。
- 物理速度/几何模型错误：对比控制关节雅可比、全关节COM雅可比和body速度，定位具体球对。
- 桌面条件豁免在运动中取消，或该行被32行活跃集遗漏：记录全量豁免与距离，核对首次进入、首次取消、首次违规时刻。

本地项目只查到仿真set_joint_position_target与评测注入FIFO，没有找到实机通信、抢占或执行器侧安全接口。执行器侧保护/队列抢占属于尚待确认的架构前提。取证完成后，按已验证的原因提出严格FIFO与执行器侧方案的不同要求，不将假设换入现有安全计数。

球层距离仍是控制周期末采样，不等于连续碰撞检测或接触力安全。独立LP只判断当前线性约束可行性，不证明动力学安全。冻结核心源码和actor；新增脚本仅采集和分析，不修改生产控制路径。

## 取证后的单因素对照预登记

两组观察重播分别11/32与1/32。原初态桌面组初态、命令、q、exec和官方球距逐位一致；延迟组仅初态与命令逐位一致，q首帧差异2.35mrad、全程最大0.982rad，仍是相同11个环境违规。这一组降级为同输入重播，不冒充原轨迹精确取证。

原候选实际backlog_aware=false，只有历史距离预测，没有单步闭合量扣减；此前文字说明需勘误。原初态env9临界桌面球在step253–257未进入32行集，期间全部32行均为cross，重入step258时已发生重叠。自碰/桌面线性约束子集未发现不可行；p未采集，不能扩展为全约束集可行结论。

因上述独立证据，登记2×2因素对照：保留原候选已完成基线，新增debit-only、critical-only和两者联合，分别复测原初态5秒与延迟10秒，共6个新cell。debit使用新显式配置，保留所有旧配置不变；critical只在评测适配器中把原预测32行与所有d <= 当前d_min+10mm的行取并集，最多128行，超出则直接中止，不静默丢弃。actor仍看到原32行、FIFO仍完整延迟6步，不新增执行器侧抢占假设。条件接触豁免仍照旧计算，但临界行也保留，防止豁免取消前无约束。

登记探针不是已经通过的生产修复。源代码core/actor冻结；更改明确记在factor_manifest.json。先比较原失败条件，不合并重复样本给独立置信界。若效果改善，还需扩大种子/任务回归才可考虑进入正式策略。
