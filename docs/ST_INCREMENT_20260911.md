## 4. 诊断：为什么容量流几乎没在「投影」

1. **自环被禁**（`st_flow_diagnosis_20260911`，已在隔离小图复现）：论文参考代码与我们的移植都把 S 对角置 0、Sinkhorn 对角 −∞，同时给**未观测边**名义容量 1/n。我们的安全格是粗格（距离/接近速度分箱 × 离合模式），一步之内「留在同一格」占主导 → 目标流 F* 只能把全部质量塞到未观测边，所有「原地保持」样本权重被压到 1/w̄=0.2（78–100% 截断）。
2. **证书集合为空**（09-12 复核，`scripts/forensics/st_solver_compare.py`）：Def. 2 的容量 S_ij = b_k ω_ij / c̄_k(i)，Σ S ≈ b_k·Σ_i p_i / c̄_k(i)。论文基准是稀疏 0/1 代价（零代价格容量 +∞，集合非空）；我们是稠密连续代价，几乎每格 c̄ > b → Σ S ≪ 1，{F ≤ S} 为空。只修 1 而不处理 2，F* 总质量只有 0.065（运动学环境 dump），所有权重仍被截到 0.2。论文的 FC 规则（Eq. 12）只会收紧（m ≤ 1），不解决这一侧。
3. 推论：E1 实际施加的不是「容量投影」，而是「把留在同一格的样本 ×0.2、格间迁移样本 ×1–5」的重加权。它带来的 −10.6 pp 误刹需要单独消融（E6）确认归因。

## 5. v2.1 修复（`safetransport_ppo.py`，commit d2f2088；旧行为可用 `--st-no-self-loops --st-unobs-cap nominal --st-cap-rescale 0` 复现）

- 自环作为合法边（D_ii = 经验 −优势，S_ii 按 Def. 2）；未观测边容量 0（F* 限于经验支撑）。
- 可行性恢复：当 Σ S < 1+η 时按 m = (1+η)·max_e F̂_e/S_e 放大 S（= 单通道下 (1+η)·max_i c̄(i)/b），使经验流可行、求解良定；最贵的格恰在容量上（w ≤ 1），增长只能去便宜格；m 作为 `cap_scale` 上报（预算距可认证的倍数），证书上界改为 m·b_k + ‖c̄‖∞·gap。
- 残差触发回退（`st_fallback_resid`）、新诊断 `diag_mass_hat/star`、`unsupported_mass`、`cap_total/cap_scale`、`w_clip_lo_frac`；`--st-dump-graph` 导出首个 rollout 的建图输入，`st_solver_compare.py` 在同一 rollout 上对比 legacy / loops / support / v21。
- 运动学环境 dump（3072 转移、31 格）：legacy w̄=0.20、clip_lo 100%、未观测边质量 0.94；v21 w̄=1.00、clip_lo 0.2%、未观测边 0、容量激活 3.1%、m=54.9（假环境 self 代价 0.4 ≫ 0.05，预期）。真实 Isaac rollout 的对比见 §6。
