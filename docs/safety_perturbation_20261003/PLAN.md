# 初态与执行延迟实验预登记

继承已发布的 `duo_env_a31_bounded_guard.yaml` 及固定 a31b checkpoint，不重复计算上一轮512窗口。物理安全源码先保持冻结，新增评测扰动独立记录。

## 评测契约

26个臂关节的初始偏移逐关节独立均匀采样，单位rad；手指、桌面/基座、动力学及观测时间保持固定。超出soft limits的初态分量裁剪并记录数量、实测有效最大偏移和RMS。采用独立初态随机数流，不消耗命令tape随机数。不拒绝碰撞初态，不把初始已违规窗口当作避碰失败或成功；总结果与初态无违规子集分别报告。

执行端延迟在安全投影和目标积分之后注入，只延迟发送到PD执行器的关节目标。延迟队列每个控制步推进一次，物理decimation子步重复同一个已延迟目标；前k步保持初始目标。测量和安全决策使用当前状态，因此这不是观测延迟，也不是输入指令延迟。每个窗口重置队列。

所有方法共享初态seed、源命令seed和命令序列；逐窗口保存初态q的SHA、命令SHA、控制器目标和真实发送目标。对比无保护、解析兜底和System 0；安全层输出量仍不能替代实际运动或任务成功。

## 首批设计

- 因果探针：seed12、32环境、10秒、随机保持1.5秒、幅度0.015、初态±0.3rad，执行延迟0/6步（约0/100ms），System 0。保留完整行/目标/实际速度轨迹。
- 初态与延迟矩阵：seed13、32环境、5秒、随机保持0.5秒、幅度0.015，初态±0.1/±0.3rad，延迟0/6步，无保护/解析兜底/System 0。若探针揭示故障，先冻结该负结果，再注册修复配置与同条件配对复测。
- 软件契约：独立初态与命令流、限位裁剪审计、相同seed重播、FIFO延迟精确序列、队列重置以及两个物理子步不能重复消费延迟队列。

## 后续登记与停止条件

零/100ms原探针在仅延长时间、完整当前目标积压和最近6个待执行目标三个候选下匹配重播。第三候选的seed13矩阵复测仅解析兜底/System 0，四个无保护控制cell从完整当前目标候选复用；其解析物理配置相同，新增目标历史仅参与保护投影，RawShim忽略投影。逐窗口初态及命令SHA核对，不增加无保护独立样本数。

最终冻结候选额外检查原初态seed11、1.5秒保持/10秒，以及seed8的5秒四臂漫游。这两个组不受初态扰动，分别报告，不替代全六臂对或全随机空间回归。

若三次策略候选仍无法消除严格FIFO的100ms延迟失效，停止继续猜测参数，保留负结果，重新确认安全指令是否能抢占队列或安全层能否在执行器侧运行。当前评测保持“全部目标，包括保护改写目标，也等待相同FIFO延迟”的严格假设；不擅自缩短保护延迟以制造零违规。

违规oracle为官方非豁免球层距离及独立球心重算审计；初态无违规是窗口起点条件，不是整个运行期安全证明。记录最小距离、违规通道、实际关节范围/路径、六臂对暴露及输出量；不汇合相关分组给独立样本安全置信界。
